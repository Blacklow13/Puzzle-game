## [ Сценарий 1 — Регистрация, вход и управление профилем ]

**Актор:** Игрок.  
**Предусловие:** Игра запущена.

1. Игрок нажимает кнопку «Регистрация».
2. Игрок вводит логин и пароль.
3. Клиент (Unity) отправляет POST-запрос на сервер Flask (`/api/auth/register`).
4. Сервер проверяет уникальность логина в базе данных SQLite.
5. Сервер хеширует пароль и сохраняет нового пользователя в таблицу `Users` через SQLAlchemy.
6. Система открывает экран входа.
7. Игрок вводит логин и пароль на экране входа.
8. Клиент отправляет POST-запрос на сервер (`/api/auth/login`).
9. Сервер проверяет хеш пароля, генерирует и возвращает **JWT-токен**, который Unity сохраняет в `PlayerPrefs` и открывает главное меню.
10. Игрок открывает раздел «Профиль» и меняет пароль. Клиент отправляет PUT-запрос (`/api/auth/password`), сервер обновляет хеш в базе данных.

**Альтернативный сценарий:**
- Шаг 4: Логин уже занят — сервер возвращает ошибку 400, клиент показывает сообщение «Логин занят».
- Шаг 9: Неверный пароль — сервер возвращает ошибку 401, клиент показывает «Неверный логин или пароль».

## [ Сценарий 2 — Запуск и прохождение уровня (начало игры) ]

**Актор:** Игрок.  
**Предусловие:** Игрок авторизован, находится в главном меню.

1. Игрок нажимает «Новая игра».
2. Клиент отправляет GET-запрос (`/api/progress`), прикрепляя JWT-токен в заголовке.
3. Сервер Flask по токену определяет пользователя и возвращает список пройденных уровней из базы данных.
4. Система показывает краткую предысторию персонажа.
5. Система загружает первый уровень и запускает таймер.
6. Игрок управляет Кроликом, осваивает лестницы и впервые взаимодействует с клоном.
7. Игрок доходит до финиша.
8. Система фиксирует результат и показывает экран завершения уровня.
9. Клиент отправляет POST-запрос (`/api/progress`) с номером пройденного уровня и JWT-токеном для сохранения результата.

## [ Сценарий 3 — Управление персонажем ]

**Актор:** Игрок.  
**Предусловие:** Уровень запущен.

1. Игрок нажимает клавишу D.
2. Система перемещает Кролика вправо.
3. Игрок нажимает клавишу A.
4. Кролик перемещается влево.
5. Игрок подходит к лестнице и нажимает W.
6. Система поднимает Кролика по лестнице.
7. Игрок нажимает S для спуска.
8. Кролик перемещается вниз по лестнице.
9. Система автоматически выравнивает Кролика по центру лестницы.

## [ Сценарий 4 — Запись действий и появление Клона ]

**Актор:** Игрок.  
**Предусловие:** Уровень запущен, таймер идёт.

1. Игрок начинает движение по уровню.
2. Система записывает каждое нажатие клавиш с временной меткой.
3. Игрок взаимодействует с объектами уровня.
4. Таймер достигает нуля.
5. Система прекращает запись движений.
6. Система создаёт Клона в стартовой точке уровня.
7. Клон начинает воспроизводить записанные действия.
8. Игрок наблюдает за действиями Клона и может дальше ходить по уровню.
9. Система синхронизирует позиции Клона и игрока по времени записи.

**Альтернативный сценарий:**
- Шаг 7: Клон не может выполнить действие (например, нет лестницы) — Клон стоит на месте, пока действие не станет возможным.
- Если игрок сталкивается с Клоном, игрок умирает, уровень перезапускается.

## [ Сценарий 5 — Взаимодействие с классами объектов ]

**Актор:** Игрок.  
**Предусловие:** Клон появился на уровне.

1. Игрок подходит к кнопке серого класса (Вечный).
2. Игрок наступает на кнопку — дверь открывается. Клон тоже может нажать эту кнопку.
3. Игрок подходит к кнопке синего класса (Прошлый).
4. Игрок наступает на кнопку до появления Клона — дверь открывается.
5. Клон может взаимодействовать с этой кнопкой после появления, игрок — нет.
6. Игрок подходит к кнопке жёлтого класса (Настоящий).
7. Только игрок может нажать эту кнопку. Клон не может взаимодействовать с ней.

**Альтернативный сценарий:**
- Шаг 5: Клон пытается нажать синюю кнопку — система игнорирует действие, ничего не происходит.

## [ Сценарий 6 — Взаимодействие с кнопками, дверями и лестницами ]

**Актор:** Игрок.  
**Предусловие:** Уровень запущен. Везде может действовать и игрок, и клон.

1. Игрок подходит к кнопке на платформе.
2. Игрок наступает на кнопку.
3. Система активирует кнопку и запускает таймер удержания.
4. Игрок удерживает кнопку 2 секунды.
5. Система открывает дверь на уровне.
6. Игрок отпускает кнопку. Дверь остаётся открытой.
7. Игрок проходит через дверь.
8. Игрок добирается до следующей лестницы.
9. Пока игрок нажимает вверх, он поднимается по ней. Спрыгнуть с неё, не долезая до конца, нельзя. Аналогично и со спуском.

## [ Сценарий 7 — Сохранение пройденных уровней ]

**Актор:** Игрок.  
**Предусловие:** Игрок прошёл уровень.

1. Система фиксирует завершение уровня.
2. Клиент (Unity) автоматически отправляет POST-запрос (`/api/progress`) с номером уровня.
3. В заголовке запроса (`Authorization: Bearer <token>`) передаётся JWT-токен игрока.
4. Сервер Flask проверяет валидность токена и извлекает `user_id`.
5. Сервер через SQLAlchemy сохраняет запись о пройденном уровне в таблицу `Progress` базы данных SQLite.
6. Сервер возвращает статус `200 OK`.
7. Игрок выходит из игры.
8. Игрок запускает игру в следующий раз и входит в аккаунт.
9. Система загружает сохранённый прогресс с сервера, и игрок продолжает с доступного уровня.

## [ Сценарий 8 — Настройки (звук и аккаунт) ]

**Актор:** Игрок.  
**Предусловие:** Игрок находится в уровне или в меню выбора уровня.

1. Игрок нажимает клавишу Esc.
2. Система приостанавливает игру (если игрок в уровне).
3. Система открывает меню с разделами: «Звук», «Аккаунт», «Продолжить», «Выйти в главное меню».
4. Игрок выбирает раздел «Звук».
5. Система отображает ползунки. При изменении клиент отправляет PUT-запрос (`/api/settings`) с JWT-токеном для сохранения настроек в БД.
6. Игрок возвращается в игру.

**Альтернативный сценарий:**
- Шаг 4: Игрок выбирает раздел «Аккаунт» — система отображает кнопки «Сменить пароль» и «Начать игру сначала».
- Шаг 5: Игрок нажимает «Сменить пароль» — клиент отправляет PUT-запрос (`/api/auth/password`). Сервер проверяет старый пароль, хеширует новый и сохраняет в SQLite.
- Шаг 5: Игрок нажимает «Начать игру сначала» — клиент отправляет DELETE-запрос (`/api/progress`). Сервер удаляет все записи о прогрессе игрока из БД, и игра начинается заново.

## [ Сценарий 9 — Меню выбора уровня ]

**Актор:** Игрок.  
**Предусловие:** Игрок авторизован, находится в главном меню.

1. Игрок нажимает «Выбор уровня».
2. Клиент отправляет GET-запрос (`/api/progress`), прикрепляя JWT-токен.
3. Сервер Flask извлекает `user_id` и возвращает JSON-список пройденных уровней.
4. Система отображает список из 7 уровней, помечая пройденные как доступные, а непройденные — как заблокированные.
5. Игрок выбирает доступный уровень.
6. Игрок нажимает «Играть».
7. Система загружает выбранный уровень и запускает таймер.
8. Игрок начинает прохождение.

**Альтернативный сценарий:**
- Шаг 5: Игрок выбирает заблокированный уровень — система сообщает звуком, что уровень недоступен.
